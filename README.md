# Java Gym Master

Учебный проект, выполненный в рамках обучения на **Яндекс Практикуме**.  
Цель проекта - с нуля спроектировать небольшую систему управления расписанием тренировок спортивного клуба и на практике отработать работу с объектной моделью Java, коллекциями, сортировкой, сравнением объектов и unit-тестами.

Проект построен без Spring и других прикладных фреймворков. Основная логика реализована средствами Java Collections Framework, а корректность ключевых сценариев проверяется с помощью JUnit 5.

## О проекте

`Java Gym Master` моделирует недельное расписание тренировок.

Система позволяет:

- добавлять тренировочные занятия в расписание;
- получать все занятия за выбранный день;
- получать занятия за конкретный день и время;
- автоматически возвращать занятия дня в порядке времени начала;
- учитывать несколько тренировок, которые начинаются одновременно;
- подсчитывать количество тренировок для каждого тренера;
- сортировать тренеров по количеству проведённых занятий по убыванию.

В рамках проекта была самостоятельно собрана вся предметная модель: тренеры, группы, время, дни недели, тренировочные занятия, структура расписания и вспомогательная модель для статистики по тренерам.

## Предметная модель

### `Coach`

Хранит данные тренера:

- фамилия;
- имя;
- отчество.

Для класса реализованы `equals()` и `hashCode()`, поэтому объекты `Coach` можно корректно использовать в качестве ключей `HashMap`.

В рамках модели Ф. И. О. используется для идентификации тренера.

### `Group`

Описывает тренировочную группу:

- название;
- возрастную категорию;
- длительность занятия в минутах.

Возрастная категория представлена enum-классом `Age`:

```java
CHILD
ADULT
```

### `TrainingSession`

Описывает одно занятие и связывает между собой:

- группу;
- тренера;
- день недели;
- время начала занятия.

### `DayOfWeek`

Enum со всеми днями недели:

```java
MONDAY
TUESDAY
WEDNESDAY
THURSDAY
FRIDAY
SATURDAY
SUNDAY
```

### `TimeOfDay`

Хранит часы и минуты начала занятия.

Класс реализует:

```java
Comparable<TimeOfDay>
```

Поэтому объекты времени имеют естественный порядок:

```text
10:00 < 13:30 < 18:00
```

Сначала сравниваются часы, а при одинаковых часах - минуты.

Также реализованы `equals()` и `hashCode()`.

### `CounterOfTrainings`

Вспомогательная модель для статистики:

```text
Coach + количество тренировок
```

Используется методом `getCountByCoaches()` для формирования итогового отсортированного результата.

## Хранение расписания

Центральный класс проекта - `Timetable`.

Расписание хранится в структуре:

```java
HashMap<DayOfWeek, TreeMap<TimeOfDay, List<TrainingSession>>>
```

Логически она выглядит так:

```text
Timetable
│
├── MONDAY
│   ├── 10:00
│   │   ├── TrainingSession
│   │   └── TrainingSession
│   │
│   └── 18:00
│       └── TrainingSession
│
├── TUESDAY
│   └── 13:00
│       └── TrainingSession
│
└── ...
```

Такое сочетание коллекций выбрано не случайно:

| Структура | Назначение |
|---|---|
| `HashMap<DayOfWeek, ...>` | быстрый доступ к расписанию нужного дня |
| `TreeMap<TimeOfDay, ...>` | автоматическое хранение временных слотов в отсортированном порядке |
| `List<TrainingSession>` | возможность хранить несколько тренировок на одно и то же время |

## Реализованная функциональность

### Добавление тренировки

```java
addNewTrainingSession(TrainingSession trainingSession)
```

Метод:

1. получает день и время тренировки;
2. создаёт расписание дня, если его ещё нет;
3. создаёт список для временного слота, если он ещё не существует;
4. добавляет новую тренировку.

Поддерживается несколько занятий в один день и несколько занятий с одинаковым временем начала.

### Получение тренировок за день

```java
getTrainingSessionsForDay(DayOfWeek dayOfWeek)
```

Возвращает все занятия выбранного дня.

Так как внутреннее расписание хранится в `TreeMap`, тренировки собираются в порядке времени начала.

Например:

```text
13:00
15:30
20:00
```

Если занятий в этот день нет, возвращается пустой список.

Поиск дня в `HashMap` выполняется в среднем за `O(1)`, но для формирования итогового списка необходимо пройти по тренировкам выбранного дня, поэтому итоговая сложность метода зависит от количества занятий и составляет `O(n)`.

### Получение тренировок за день и время

```java
getTrainingSessionsForDayAndTime(
    DayOfWeek dayOfWeek,
    TimeOfDay timeOfDay
)
```

Возвращает все тренировки, начинающиеся в указанный день и время.

Поиск дня в `HashMap` выполняется в среднем за `O(1)`, а поиск времени в `TreeMap` - за `O(log n)`.

### Подсчёт тренировок по тренерам

```java
getCountByCoaches()
```

Метод проходит по всему недельному расписанию и формирует:

```java
HashMap<Coach, Integer>
```

где:

```text
ключ      -> Coach
значение  -> количество его тренировок
```

После подсчёта данные преобразуются в:

```java
List<CounterOfTrainings>
```

и сортируются по количеству тренировок по убыванию.

Пример результата:

```text
Тренер A -> 5
Тренер B -> 3
Тренер C -> 1
```

Для корректной работы `Coach` как ключа `HashMap` в классе переопределены `equals()` и `hashCode()`.

## Тестирование

Для проверки расписания используется **JUnit 5**.

В `TimetableTest` реализованы тестовые сценарии для основных операций поиска занятий.

### Одна тренировка за день

Проверяется, что:

- занятие корректно возвращается за нужный день;
- возвращается именно добавленный объект;
- для дня без занятий возвращается пустой список.

### Несколько тренировок

Проверяется:

- количество занятий;
- получение тренировок за разные дни;
- корректная сортировка занятий по времени.

Отдельно проверяется сценарий, когда занятия были добавлены не в хронологическом порядке, но возвращаются в правильном:

```text
13:00
20:00
```

### Поиск по дню и времени

Проверяется:

- получение существующего занятия;
- отсутствие занятий для другого временного слота.

## Запуск

Проект представляет собой обычный Java-модуль.

Для работы с ним:

1. Клонируйте репозиторий:

```bash
git clone https://github.com/kemuri-ni-deteitta/java-gym-master.git
```

2. Откройте проект в IntelliJ IDEA.
3. Убедитесь, что для проекта выбран JDK.
4. Для запуска тестов откройте `TimetableTest` и запустите тестовый класс через IntelliJ IDEA.

JUnit 5 используется для тестового исходного кода в директории `test`.
